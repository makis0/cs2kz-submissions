# A release renders a copiable Discord announcement as a fourth, side-effect-free shape over the ordered manifest

When a release is about to ship, the map approval team posts an announcement in Discord pinging the game's server operators: a fixed header, an `ansi` code block with one line per map (`map_name (T5):workshop_id`, the tier coloured), and a sign-off. It was written by hand from the release's maps, re-deriving tiers and workshop ids the portal already holds.

Decision: the portal renders that announcement as text, the way it renders the Release export (ADR-0008) — shown in a modal with a copy button, never sent by the server. It is a third formatting adapter over the ordered manifest (ADR-0012): `toReleaseDiscordMessage` (`server/utils/release-discord-message.ts`) is a pure shape-mapper, `build-discord-message.ts` the bound resolve-then-shape wrapper, and `GET /api/{game}/releases/{id}/discord-message` returns `{ message }`. Map lines follow manifest order. Each map's tier is the **nub tier of its first course in the game's first Course mode** (CKZ for CS2, KZT for CS:GO), shown on the site's 1..10 scale; colours are green for T1–T2, blue for T3, yellow for T4 and red from T5. The mention is a real `<@&roleId>` when the game's optional `NUXT_DISCORD_{CS2,CSGO}_SERVER_OPERATOR_ROLE_ID` is set, and readable plain text (`@CS2 - Server Operator`) otherwise. A first course without that finalized filter is a 400 naming the map and course; an empty release is a 400.

Like the image pack and unlike the JSON export, the announcement has no side effect: generating it never marks the release exported, because announcing a release (≈48 hours ahead) happens before it is imported.

Considered: posting through the existing notifications webhook. Rejected: the team reviews and edits the text before posting, the announcement channel is not the notifications channel, and a server-side post would need its own retry and idempotency story. Considered: the hardest tier across all courses, or the pro tier. Rejected by the map approval team: the announcement has always shown the main course's CKZ nub tier.

Consequences: the announcement covers new maps only. The hand-written "updated map" section (a map whose workshop id changed, with GLOBAL and NON-GLOBAL ids) has no source in the data model and is out of scope until map updates are modelled. A message over Discord's 2000-character limit is a UI warning, not a refusal; the operator splits it.
